# Spec: Feature #32 — sell/find: исправление закрытия модалки при повторном pjax-поиске

## Обзор

На странице продаж (`sell/index`, `sell/index-v2`) кнопка «Axtarış» открывает модальное окно `#sell-modal`, в которое через `.load()` подгружается `sell/find` (`SellController::actionFind` → `renderAjax`). Первый поиск отрабатывает нормально. При втором поиске модальное окно закрывается само по себе: срабатывает обработчик `hidden.bs.modal` → `window.location.replace(sellHomeUrl())`.

**Влияние на бизнес:** кассир не может выполнить второй поиск товара без потери контекста — приходится заново открывать модалку. Прямой ущерб рабочему процессу продаж.

## Роли пользователей

| Роль     | Описание                                                  |
|----------|-----------------------------------------------------------|
| Кассир   | Выполняет продажи, ищет товары через модалку sell/find    |

## Функциональные требования (FR)

1. **FR-1** (из AC-1): Система должна допускать ≥ 3 последовательных поисков в модалке `sell/find` без её закрытия. Результаты обновляются корректно после каждого поиска.
2. **FR-2** (из AC-2): После каждого pjax-обновления грида фокус возвращается в поле `#name`.
3. **FR-3** (из AC-3): Функция `addSell` работает корректно после нескольких поисков — добавляет товар в чек и обновляет `#grid-arrival` на хост-странице.
4. **FR-4** (из AC-4): URL хост-страницы (`sell/index` или `sell/index-v2`) не изменяется на `sell/find?...` в процессе поиска внутри модалки.
5. **FR-5** (из AC-5): Закрытие модалки пользователем (крестик / Esc / клик вне) работает штатно и вызывает `window.location.replace(sellHomeUrl())`.
6. **FR-6** (из AC-6): Поведение при поиске идентично на `sell/index` и `sell/index-v2`.

## Нефункциональные требования (NFR)

1. **NFR-1 — Производительность pjax:** обновление грида при поиске не должно вызывать полную перезагрузку страницы. Время отклика pjax-запроса не должно превышать текущего baseline (нет регрессии производительности).
2. **NFR-2 — Совместимость:** исправление должно работать одинаково на `sell/index` и `sell/index-v2` без дублирования кода (единая точка изменения в `main.js` или общем шаблоне).
3. **NFR-3 — Стабильность ID виджетов:** решение должно устранить коллизию авто-ID виджетов (Kartik GridView, Select2) между хост-страницей и содержимым модалки.

## Scope

### В Scope

- Исправление обработчика `hidden.bs.modal` в `web/js/main.js` — разграничение штатного закрытия от pjax-события
- Отключение `pushState` для pjax грида `sell/find` (или иное предотвращение изменения URL хост-страницы)
- Устранение дублирования pjax-обработчиков при повторном открытии модалки
- Устранение коллизии авто-ID виджетов при `renderAjax`
- Возврат фокуса в `#name` после каждого pjax-обновления
- Проверка работоспособности `addSell` на `sell/index` и `sell/index-v2`

### Вне Scope

- Редизайн модалки поиска и изменение набора колонок/фильтров
- Мобильная версия (`sell/find-mobile`, `#sell-modal-mobile`)
- Аналогичные модалки поиска в других модулях (arrival/find, transfer и т.д.) — только если фикс тривиально переиспользуется, иначе отдельный issue
- Изменения в логике `RestSearch` / SQL поиска

## Технический контекст

### Архитектура проблемы

```
sell/index (хост-страница)
  └─ #sell-modal (Bootstrap modal)
       └─ .load('sell/find') → renderAjax('find')
            └─ kartik GridView #w0 (pjax, pushState=true по умолчанию)
```

### Корневые причины

1. **Коллизия ID виджетов:** `renderAjax('find')` сбрасывает счётчик авто-ID виджетов Yii2 до `w0` при каждой загрузке в модалку. Это создаёт конфликт ID с виджетами хост-страницы (Kartik GridView `#grid-arrival`, Select2 и т.п.). После первого pjax-обновления JS `yiiGridView`/pjax/Select2 инициализируется на чужие элементы, что нарушает работу модалки.

2. **pushState изменяет URL хост-страницы:** pjax грида `sell/find` по умолчанию использует `enablePushState=true`. При pjax-запросе URL браузера меняется на `sell/find?...`, что может инициировать нежелательные события Bootstrap modal.

3. **Дублирование pjax-обработчиков:** `$(document).on('pjax:complete', …)` в `views/sell/find.php` навешивается повторно при каждом открытии модалки (`.load()` не очищает старые обработчики).

4. **Обработчик hidden.bs.modal:** в `web/js/main.js` обработчик `$("#sell-modal").on('hidden.bs.modal')` вызывает `window.location.replace(sellHomeUrl())`. Этот обработчик срабатывает не только при штатном закрытии, но и при любом другом событии `hidden`, в т.ч. вызванном pjax-навигацией.

### Файлы под изменение

- `web/js/main.js` — основная логика обработчиков модалки
- `views/sell/find.php` — kartik GridView с pjax, обработчики событий
- `views/sell/index.php` — хост-страница (возможно)
- `views/sell/index-v2.php` — хост-страница v2 (возможно)
